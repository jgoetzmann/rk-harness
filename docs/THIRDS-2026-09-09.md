# Equal thirds: explicit, adaptive and implicit get the same standing

Status as of 2026-09-09: **batches 1 to 7 landed, the rotation is not armed.** The container
behaves as it always has, one explicit search per cycle. What has changed is that the split is
now data rather than a sentence, the two side classes have open-ended work waiting, the site
gives each class a page, and every host viewer knows what a lane is before any lane exists.

This note is the plan. `docs/LANES.md` and `docs/LANESEARCH.md` describe the two machines it
builds; `docs/DECISIONS.md` D33 to D36 carry the rulings made along the way.

## 1. What the survey found, and why the refactor is not cosmetic

`docs/ROADMAP.md` has described a 70/15/15 split of attention since 2026-09-02. A survey on
2026-09-09 measured the preceding 186 cycles: 0.16 s of about 32,700 s reached adaptive and
implicit combined. That is 0.0005 percent against an intended 30.

Neither number was wrong when it was written. The intention lived in a sentence in a document
and the outcome lived nowhere at all, so nothing in the system was in a position to notice them
drifting apart. Three structural facts kept the gap open:

* Cycle 2726 spent 73 s on archive replay, 15 s on the directive, 64 s on four CMA-ES islands,
  18 s verifying and 6 s on the rest. The explicit search proper is 36 percent of a cycle;
  everything serving the explicit archive is 97.
* The two side tracks share one bounded 180 s slot every 20 cycles. That caps them at 4.9
  percent COMBINED even when the slot is full.
* The 103-point side-track catalogue has been complete since cycle 2540, so every firing since
  has logged `sidetrack_exhausted` in about 0.05 s. The slot was not merely small, it was empty.

The third fact is the one that orders the work. Giving the two lanes a third of the machine
before they have open-ended work would hand them a third of the clock and an empty queue.

## 2. The rule the batches follow

Every batch before B10 ships INERT or READ-ONLY, and says which in its own docstring. A batch
may add a module nothing calls, a document no page reads, or a viewer row that renders what
already exists. No batch before B10 changes what a cycle does.

Two invariants hold across all twelve, and each batch states them in its commit:

* `VERIFIER_HASH` stays `de5bec22...fd6e9`. Changing a pinned file is an epoch boundary, not a
  batch. The ten files are listed in CLAUDE.md rule 1.
* `sidetrack.code_hash()` stays `305c692a1b5c085a`. Moving it re-opens every measured
  side-track point, which is 103 points of work thrown away for an edit.

### The two axes, which B3 introduced and B6 cannot yet publish

Axis F is error at a fixed 65,536-cycle budget. That is what the scored archive measures and it
is the only axis an explicit fixed-step method has. Axis T is cycles-to-tolerance, and it is the
only axis on which an adaptive method can be compared at all: a method that chooses its own step
count cannot be scored at a step count chosen for it.

`rk-work/validation/axes.json` is where axis T lands. It is **not** on the traceability list
(CLAUDE.md rule 11), so no number from it reaches a page today. The class pages detect it, name
it, and say it has not been written. See section 5.

## 4. What B6 and B7 actually changed

B6 made `index.html` a hub: the three classes, the boundary between them, and one traced number
each with explicit first. The archive it used to carry moved verbatim to a new `explicit.html`.
`implicit.html` and `adaptive.html` are new and unconditional, so a fresh work directory still
writes all three; `sidetrack.html` keeps its filename and becomes provenance only. Nav is three
rows. Every `cell-*.html` filename and every inbound link is unchanged.

Absent data is the primary case, not the edge case, because a fresh work directory is what an
epoch starts from. With no ledger the class pages say so in a sentence and emit no card row at
all, rather than an empty table or a zero that reads as a measurement that came back empty.

B7 made the viewers lane-aware BEFORE the rotation is armed, which is the whole reason it
precedes B10. Every host viewer currently reads "cycle" as "explicit search": the stall counter,
the saturation orchestrator, `stats.txt` and the watcher all assume a cycle that appends nothing
to the scored archive has failed. Arming first would mean a release where a cycle that did
exactly what it was told reports a fault. `status.read_lanes` and `status.lane_rows` are the
single reader, so the watcher and `stats.txt` cannot disagree.

`saturation.py` is the viewer with teeth and B7 did not reach it; D35 finished it. Its 48-hour
no-progress rule counted wall clock, which was the same quantity as search time only because
every cycle was an explicit search. It now measures the window in explicit-lane seconds and
falls back to wall clock, saying which measure ran.

## 5. What the owner still decides

**Does `rk-work/validation/axes.json` join the traceability list?** CLAUDE.md rule 11 names four
permitted sources. `axes.json` is not one, so axis T cannot be published, and axis T is the only
axis on which adaptive methods can be compared. Until this is decided the adaptive page carries
ledger readings and class definition but no comparison. The loader, the presence panel and the
glossary entries are already in place, so admitting it is a contained follow-up rather than new
work. The same question applies separately to the two lane archives, whose own records argue
against admission and which the class pages name either way.

**D26's two questions** on arming the exploration policy, and **P02's Q31** cost-model term, are
unchanged and still open.

## 6. Arming, when the time comes

Do not arm B10 until B8 has refilled the catalogue or B9 has pointed the lanes at `lanesearch`.
A lane with an empty queue gets a third of the clock and returns in 0.05 s.

Three runner changes must land with the arming, not after it:

1. Write `rk-work/schedule/cycles.jsonl` and refresh `shares.json` each cycle. Until this exists
   the "measured" row correctly says unknown, and `saturation` correctly falls back to wall
   clock.
2. Add a `lane` field to `cycle_done`. `accept_rate` self-arms from the stream: no cycle carries
   one today and every one is counted, exactly as before.
3. `stall_counter` advances only on an explicit lane. The armed wording of the stall row already
   asserts this; without the runner change the row explains a counter that is still counting
   lane cycles.

Two host values need re-deriving at the same time: `watchdog.no_candidate_minutes`, currently 30,
should become the longest run of non-E letters plus one, times cycle length; and
`LANE_SHARES_STALE_CYCLES` in `status.py`, currently 20, is derived from the 176 s cadence
measured 2026-09-09.

`scripts/run.ps1` needs its `-e RK_LANE_SCHEDULE` line before the lane row can report anything
but "container sets none".
