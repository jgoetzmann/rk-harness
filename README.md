# rk-harness

rk-harness searches for Runge-Kutta integrators that stay accurate in Q15 fixed point (int16
with a floor multiply) on a Cortex-M0+ cycle model. A container runs the search unattended,
checks every candidate with an exact verifier it cannot edit, and publishes what it finds as a
static website.

| --- | --- |
| [Overview site](https://jgoetzmann.github.io/rk-overview/) | Start here. What the project is, how it is built and why, what it found, and an in-browser demo. |
| [Live findings](https://jgoetzmann.github.io/rk-findings/) | The numbers, regenerated by the run every cycle. |
| [rk-work](https://github.com/jgoetzmann/rk-work) | Run data: the archive, the hypothesis ledger and the measurement outputs. |
| [rk-findings](https://github.com/jgoetzmann/rk-findings) | Source of the findings site. The run writes it and nobody edits it by hand. |
| [rk-overview](https://github.com/jgoetzmann/rk-overview) | Source of the overview site and the tools that build it. |

## What it does

In floating point a coefficient like 1/3 costs the same as 1/4, so cheap coefficients only
matter on a chip without an FPU. On a Cortex-M0+ running Q15, a power-of-two coefficient is a
shift instead of a multiply, and int16 rounding error competes with truncation error. The
harness looks for Butcher tableaus that give the lowest end-to-end error for a fixed cycle
budget under those conditions. Every result goes into an append-only archive along with the
hash of the code that scored it, so any number can be checked later.

## How it works

### The container and its gate

The `Dockerfile` builds a Python 3.12 image with the pinned dependencies and the Codex CLI. The
harness is not copied into it. It is mounted read-only at `/harness`, beside writable checkouts
of rk-work (`/work`) and rk-findings (`/findings`), so the process being scored has no way to
edit its scorer.

`entrypoint.sh` writes a heartbeat, exits if `/harness` is writable (canary K4), checks the
verifier hash (K3), and runs the golden tests G1 to G20 and canaries K1 and K2. Only then does
it start `python -m rk_harness.runner`.

### The verifier hash

Ten files decide every score:

```
rk_harness/coeffrep.py        rk_harness/orderconditions.py
rk_harness/verifier.py        rk_harness/costmodel.py
rk_harness/evaluator.py       rk_harness/problems.py
fixtures/classical.json       fixtures/problems.json
fixtures/q15.json             fixtures/known_sequence.s
```

`VERIFIER_FILES.txt` lists them and `VERIFIER_HASH` holds their sha256. Every archived record
carries the hash that produced it. Changing one of these files starts a new epoch (see
[Rules for changing code](#rules-for-changing-code)). The rest of the package can change
without moving a score.

### The cycle loop

On an explicit cycle the runner asks the encourager for the next action and takes a search
direction from the model or from a deterministic fallback. It generates candidates, by
exhaustive enumeration in phases 0 and 1 and afterwards by CMA-ES over the free coefficients
with exact projection onto the order conditions. It evaluates them and sends the survivors
through the verifier. Accepted records go into a MAP-Elites archive whose cells are keyed by
order, stage count and cycle-cost bucket.

The runner then updates run state, rebuilds the findings site and commits into `/work` and
`/findings`. It never pushes: a watchdog on the host pushes both repos on a timer, and no push
credential enters the container. The model is optional (`RK_LLM`) and only chooses directions.
The optimizer has no code path to the held-out problem set.

### Three method classes

`RK_LANE_SCHEDULE` gives each cycle a letter: `E` explicit, `A` adaptive, `I` implicit. `E`,
every cycle explicit, is the default. `EAI` rotates through all three.

| | Explicit | Adaptive | Implicit |
| --- | --- | --- | --- |
| Method family | fixed-step explicit RK | embedded pair plus a step-size controller | 2-stage SDIRK |
| Search | enumeration, then CMA-ES | deterministic enumeration (`lanesearch.py`) | deterministic enumeration (`lanesearch.py`) |
| Question | error at a fixed cycle budget | cycles to reach a tolerance | cycles to reach a tolerance |
| Problems | the frozen set in `problems.py` | the application problems in `validation.py` | the application problems in `validation.py` |
| Arithmetic | Q15 | float64, with Q15 prices on the attempt count | float64 (there is no Q15 LU) |
| Checked by | the pinned verifier and cost model | nothing pinned; not order-verified, not scored | nothing pinned; not order-verified, not scored |
| Archive | `rk-work/archive/` | `rk-work/adaptive_archive/` | `rk-work/implicit_archive/` |

The two lane archives are unpinned and sit off the scored path, so a lane record cannot be
compared with a scored record. Every cycle also appends a row to
`rk-work/schedule/cycles.jsonl`. Separately, the side-track executor (`sidetrack.py`) measures a
fixed catalogue of adaptive and implicit jobs into `rk-work/sidetrack/`. It stays off unless
`RK_SIDETRACK_EVERY` is set.

### Epochs

`saturation.py` assesses whether the current epoch has stopped producing new or better
records. It only reports. Freezing is a person's decision unless the watchdog runs with
`-AutoFreeze`. The encourager also applies two calendar rules: PACKAGE from 2026-11-20 and
FREEZE from 2026-12-05.

### The sites

`sitegen.py` and `methodology.py` write the findings site into `rk-findings/docs/` on every
cycle. The output is deterministic and has no JavaScript, and a banned-word check can block the
whole build. The overview site is built separately by `rk-overview/tools/generate.py`, which
imports some sitegen helpers and reads this repo's test collection.

The findings pages read the scored archive, `validation/results.json`,
`benchmark/results.json`, `falsification.json`, the hypothesis ledger, the side-track ledger and
the artifacts it names, and the two lane `elites.json` documents, all in rk-work. The research
log also shows the newest literature digests and interpretations as model-written text, and the
epoch panel on the index reads `events.jsonl`, `saturation_state.json` and `EPOCH_STATUS.json`.
The implicit and adaptive pages list `validation/axes.json`, `schedule/shares.json` and the
per-day lane records under "Further evidence, not published here" and quote nothing from them.

## Getting started

You need Python 3.12 or newer; the image and CI use 3.12. The dependency pins are in
`pyproject.toml`. The package is never installed, and `pip install -e .` fails: the flat layout
puts `docs/`, `fixtures/`, `scripts/` and `tests/` beside the package, which defeats
setuptools auto-discovery. Run everything from the `rk-harness` directory, where `python -m`
finds the package. The container and CI set `PYTHONPATH` to the checkout instead.

Windows (PowerShell):

```powershell
cd rk-harness
python -m venv .venv
.venv\Scripts\python.exe -c "import tomllib; p=tomllib.load(open('pyproject.toml','rb'))['project']; open('.venv/requirements.txt','w').write('\n'.join(p['dependencies']+p['optional-dependencies']['test']))"
.venv\Scripts\python.exe -m pip install -r .venv\requirements.txt tzdata
```

Windows ships no time zone database, and the site and viewers show US Central time through
`zoneinfo`, so the Windows venv also needs `tzdata`. It is not in `pyproject.toml`.

Linux or macOS (bash):

```bash
cd rk-harness
python3 -m venv .venv
.venv/bin/python -c "import tomllib; p=tomllib.load(open('pyproject.toml','rb'))['project']; open('.venv/requirements.txt','w').write('\n'.join(p['dependencies']+p['optional-dependencies']['test']))"
.venv/bin/python -m pip install -r .venv/requirements.txt
```

The tests and a local cycle with the model off need no credentials. The container and the
watchdog read `.env`: copy `.env.example` to `.env` and fill in `GITHUB_TOKEN` (host only, used
for pushes), `OPENAI_API_KEY` and `OPENAI_MONTHLY_CAP_USD`.

The commands below use the Windows venv path. On Linux or macOS, use `.venv/bin/python`
instead.

## Tests

```powershell
# fast subset: every test not marked slow
.venv\Scripts\python.exe -m pytest tests -m "not slow"

# the container's own gate, in the order entrypoint.sh runs it
.venv\Scripts\python.exe -m rk_harness.verifier_hash --check
.venv\Scripts\python.exe -m pytest tests -rN -k "G1_ or G2_ or G3_ or G4_ or G5_ or G6_ or G7_ or G8_ or G9_ or G10_ or G11_ or G12_ or G13_ or G14_ or G15_ or G16_ or G17_ or G18_ or G19_ or G20_ or K1_ or K2_"

# checkout hygiene: every rule the repo states about itself
.venv\Scripts\python.exe scripts\hygiene.py --all

# the full suite
.venv\Scripts\python.exe -m pytest tests
```

The fast subset takes a couple of minutes. The full suite takes much longer, and on a machine
that is also running the container it loads the host enough that the watchdog pauses the run.
`conftest.py` points every test at a throwaway work directory and turns the site and the model
off, so no test touches a real archive. `tests/golden_gate.txt` records the node ids the gate
selects: `hygiene.py --gate-coverage` checks it, and adding `--write` regenerates it after an
intended change.

`scripts/preflight.py` is the pre-run review. `--docker` adds the container checks, `--quick`
runs only the fast tests, and `--no-suite` skips pytest. `--reuse-suite` reads
`.fullsend/preflight-junit.xml` instead of running the suite, for example a result downloaded
from CI's `preflight-suite` artifact.

### What CI runs

`.github/workflows/ci.yml` runs on pushes to `main` (unless the push only touches `docs/` or
`README.md`), on pull requests, and by hand. Everything runs on GitHub-hosted Ubuntu with
Python 3.12.

| Job | What it checks |
| --- | --- |
| `gate` | The verifier hash matches its pin, the golden and canary tests pass, and the gate still collects `tests/golden_gate.txt`. |
| `suite` | The test files in five shards: t1; t2, t5, t6 and t7; t3 and t9; t4, t11, t12 and t13; t8 and t10. |
| `suite-evidence` | Merges the shard results and uploads them, with provenance, as the `preflight-suite` artifact. |
| `hygiene` | Every `.ps1` is ASCII and parses under PowerShell 7, `entrypoint.sh` is LF, `VERIFIER_FILES.txt` matches the pinned tuple, the gate expression is identical everywhere, and every test tier is described in rk-overview's `_SUITE_DESC`. |
| `determinism` | The prototype curves and the whole side-track catalogue come out byte-identical across two runs, no scored file gets written, and the hash still matches. |
| `image` | The image builds, the gate passes inside it, and the harness mount is read-only. |
| `pins` | The Dockerfile and `pyproject.toml` pin the same versions. |

The shards only cover t1 to t13. `test_t14_secondpass.py`, `test_t15_stiffscreen.py`, the
three `test_t16_*` files, `test_t17_validation_axes.py` and `test_t18_class_pages.py` do not
run in CI, so a suite reused through `preflight.py --reuse-suite` leaves them out too. Run them
locally before pushing a change to the lanes, the lane search, the
validation axes, second-pass metrics, the stiff screen or the class pages.

## Running one cycle locally

```powershell
$env:RK_WORK_DIR = "..\scratch\work"
$env:RK_FINDINGS_DIR = "..\scratch\findings"
.venv\Scripts\python.exe -m rk_harness.runner --once
```

With nothing else set, the model is off and nothing is committed. The site is rebuilt into
`$env:RK_FINDINGS_DIR\docs`; set `RK_SITE=off` to skip that. `--cycles N` runs N cycles. A file
named `STOP` in the work directory makes the runner exit at the next cycle boundary. Only point
these variables at real rk-work and rk-findings checkouts if you mean to add to the real
archive, and never while the container is using them.

Other entry points, run from the `rk-harness` directory. All except `verifier_hash` take the work
directory from `RK_WORK_DIR`.

| Command | What it does |
| --- | --- |
| `python -m rk_harness.watch` | Live terminal view. `--once` prints one frame, `--cells` only the per-cell table. |
| `python -m rk_harness.status` | Writes `stats.txt` beside the work directory. `--age` reports the file's age without probing anything: exit 0 current, 1 stale, 2 unreadable. |
| `python -m rk_harness.saturation` | Read-only epoch assessment. `--check` advances the counter; `--mark-frozen "reason"` freezes the epoch. |
| `python -m rk_harness.verifier_hash` | Prints the hash. `--check` compares it with the pin; `--pin` rewrites `VERIFIER_HASH`, which only an epoch boundary should do. |
| `python -m rk_harness.archive` | `--checkpoint` writes `ARCHIVE_CHECKPOINT.json`; `--verify-checkpoint` compares it with a full replay. |
| `python -m rk_harness.sidetrack` | Side-track executor: `--status`, `--plan`, `--run-one`, `--run-until SECONDS`, plus `--tracks`. |
| `python -m rk_harness.lanesearch` | One lane search step by hand: `--lane adaptive` or `implicit`, `--status`, `--budget`, `--dry-run`. |
| `python -m rk_harness.lanes` | Aggregates the cycle log into `schedule/shares.json`; `--dry-run` prints it instead. |
| `python -m rk_harness.validation` (also `benchmark`, `validation_axes`, `secondpass`, `stiffscreen`, `falsification`) | Runs that module's measurement. |

To rebuild the findings site on the host with both variables set:

```powershell
.venv\Scripts\python.exe -c "from rk_harness import archive, sitegen; from rk_harness.paths import findings_dir; sitegen.build(archive.replay(), findings_dir() / 'docs')"
```

## Running the container

This part assumes a Windows host with Docker Desktop on the WSL 2 backend. The scripts target
Windows PowerShell 5.1.

The day-to-day scripts belong in a workspace directory that holds the rk-harness, rk-work and
rk-findings checkouts side by side. `scripts/workspace/` has a copy of each: copy them into that
directory and rename `config.example.json` to `config.json`.

```powershell
.\start.ps1 -Build                              # build the image, start the container, the watchdog and the stats writer
.\stop.ps1                                      # write STOP, wait for the cycle boundary, stop the watchdog
.\stop.ps1 -Force                               # docker stop now
python configure.py explain                     # every key, its range, and what must restart
python configure.py set run.lane_schedule=EAI
```

`config.example.json` does not include the lane keys (`run.lane_schedule`,
`run.lane_max_seconds`, `run.lane_max_candidates`). Without them `start.ps1` uses `E`, 180 and 0.

`start.ps1` turns `config.json` into arguments for the two scripts below, which you can also run
directly:

```powershell
.\scripts\run.ps1 -Build -Harness C:/path/to/rk-harness -Work C:/path/to/rk-work `
  -Findings C:/path/to/rk-findings -EnvFile C:/path/to/rk-harness/.env
.\scripts\watchdog.ps1 -Work C:/path/to/rk-work -Findings C:/path/to/rk-findings `
  -EnvFile C:/path/to/rk-harness/.env -LogFile C:/path/to/watchdog.log
```

`run.ps1` refuses to start without the three directories, the `.env` file and a pinned
`VERIFIER_HASH`. With `-Build` it builds `rk-harness:latest`. It creates the `rk-net` bridge if
it is missing (then run `scripts/network.sh` inside WSL as root to apply the egress allowlist),
replaces any old `rk` container, and starts a new one. The new container gets
`--restart on-failure:5`, CPU, memory and process caps, a tmpfs scratch directory, the three
mounts, the `.env` values minus `GITHUB_TOKEN`, and the `RK_*` settings from its parameters.
When `~/.codex/auth.json` exists, `run.ps1` mounts it read-only and `-Llm auto` resolves to
`codex`. Without it, `auto` resolves to `off`.

`watchdog.ps1` polls every 10 seconds. It pushes rk-work and rk-findings on a timer, kills the
container when the heartbeat goes stale, and stops it on low disk or spend over the cap. It
pauses the container while the machine is on battery or busy with other work, and resumes it
afterwards. It also runs the saturation check, which only logs unless `-AutoFreeze` is given.
Pass `-LogFile`: `rk_harness.status` reads the tail of that file into `stats.txt`.

The image holds only the dependencies and `entrypoint.sh`, and the code comes from the mount.
After a code change, restart the container. After a change to the `Dockerfile` or
`entrypoint.sh`, rebuild with `-Build`.

To stop at a cycle boundary, create `STOP` in rk-work (this is what `stop.ps1` does). The runner
exits with code 0, so the restart policy leaves it down. Delete `STOP` before starting again.
`docker stop rk` is the hard stop. To restart, run `run.ps1` again without `-Build`. State
replays from rk-work, and an interrupted cycle is lost. `docker logs -f rk` shows the hash
check and the gate; after that the runner writes events to `rk-work/events.jsonl`.

## Rules for changing code

1. **The ten pinned files are an epoch boundary, not an edit.** Changing one invalidates every
   score in the archive. The container refuses to start on a mismatch, and CI fails. Re-pinning
   is never a routine step. The sequence is: freeze the epoch, edit the pinned files and any
   golden values the change is meant to move, run `python -m rk_harness.verifier_hash --pin`
   last, rebuild the image, and start a new archive. Some golden values sit in `fixtures/`,
   which is pinned, so pinning before those edits leaves a hash the container rejects. The old
   records keep their old hash,
   which is how the two epochs stay distinguishable. Importing the pinned modules is fine, and
   so is changing anything else in the package. Leave `entrypoint.sh`, the `Dockerfile` and
   `VERIFIER_HASH` alone without a good reason.
2. **PowerShell files must be pure ASCII.** Windows PowerShell 5.1 will not parse smart quotes
   or em dashes, even though PowerShell 7 accepts them.
3. **`entrypoint.sh` must stay LF.** With CRLF the container dies with
   `exec: no such file or directory`. `.gitattributes` disables line-ending conversion for the
   whole repo.
4. **Findings pages stay deterministic and free of JavaScript.** The same inputs must give
   byte-identical output: no wall-clock reads, no randomness, sorted iteration. Interactivity is
   `<details>` and links. One banned word on any page blocks the whole build.
5. **Store UTC, display US Central** (`timefmt.py`). Never convert on the way into a file.
6. **Subprocess text is UTF-8**, with `encoding="utf-8", errors="replace"`.
7. **Viewers do not import the runner.** `watch.py` and `status.py` read state files.
8. **A new `tests/test_tN_*.py` tier needs a line in rk-overview.** The overview build and CI's
   `hygiene` job both fail until `_SUITE_DESC` in `rk-overview/tools/generate.py` describes it.
   Put new tests in an existing file when one fits.
9. **Published numbers come from named sources.** The findings pages read the documents listed
   under [The sites](#the-sites). The overview adds its own `key_findings.json`, computed from
   the archive, and facts about this repository such as the test count. `docs/DECISIONS.md`
   records which run documents a page may quote and which it may not (D24, D39, D40). A
   side-track number carries its job's arithmetic string, and a lane elites number carries its
   metric, its arithmetic and the fact that it is not order-verified.
10. **Record rulings in `docs/DECISIONS.md`**, in the shape of the existing entries, including
    the epoch-impact line.
